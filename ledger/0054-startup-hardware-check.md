# 0054 — Стартовый скрипт: проверка оборудования; две ошибки, гасившие друг друга

**Дата:** 2026-08-13
**Статус:** ✅ проверка проходится по-настоящему
**Тип:** отладка, разбор чужого кода, инструменты

Продолжение 0052. Исправление builtin 70 увело исполнение **другой веткой**, и
это оказалось полезнее самого исправления: стало видно, что стартовый
`firstIdle` — не «инициализация», а **проверка оборудования**.

## Две ошибки, которые гасили друг друга

С правильным builtin 70 (логическое «не») книга пошла показывать сообщение
«В системе "WINDOWS" на Вашем компьютере не обнаружено звукового устройства».
Печать операнда показала причину:

    builtin 70 получил 0 (ширина 4, стр «true»)

То есть `myMCITest` вернул логическое **`true`** — проверка прошла, — но
материализация логического значения в число давала 0. Раньше это гасилось
перевёрнутым builtin 70: 0 при правиле «≥1» тоже давало 0, и путь случайно
совпадал с верным. Две ошибки в паре неотличимы от правильной работы, пока не
исправишь одну.

Исправлено по-настоящему: логические значения ToolBook — канонические строки
`true`/`false`, при материализации в числовой тип дают 1/0. Заодно `truth()`
перестал считать строку `false` истиной (она ведь непустая).

## Что проверяет стартовый скрипт

Строки книги (CP1251) прямо перечисляют условия: 256 цветов, шрифт
«Small Fonts», подсистема «Video for Windows», звуковое устройство, наличие
`C:\WINDOWS\MTB40.INI`. При провале — «Необходимо повторить установку
программы».

## Эталонный стенд отдал недостающие файлы

Диск гостя можно прочитать **не поднимая машину**:

    qemu-img convert -U -O raw vm/win98.qcow2 win98.raw
    hdiutil attach -imagekey diskimage-class=CRawDiskImage -readonly -nomount win98.raw
    mount -t msdos -r /dev/diskNs1 mnt

(`-U` обязателен: если стенд запущен, образ заблокирован на запись.)

Оттуда взято:

* `C:\WINDOWS\MTB40.INI` — всего две строки, `[CACHE FILES]` и
  `KNTOWER.EXE=C:\NMG\KNTOWER\KNTOWER.TBC`. Это же снимает вопрос о порядке
  аргументов `getIniVar`: секция и ключ теперь известны по факту, а не по
  догадке;
* `C:\NMG\KNTOWER\` — установка: `KNTOWER.TBC` (кэш скомпилированных скриптов,
  1.2 МБ), `SCORES.INF`, `NAMES.SAV`, `README.TXT`.

README попутно объясняет две вещи об игре: `SCROLL=ON/OFF` в `SCORES.INF`
влияет на прерывания звука в прологах, а Shift при щелчке по заданию
пропускает пролог.

Файлы перенесены в дерево игры, чтобы оно повторяло эталонную установку.

## Таблица встроенных функций — теперь адрес любого builtin

В обработчике опкода 0x2c нашёлся косвенный дальний вызов
`lcall cs:[bx + 0x1bfa]`, где `bx = id * 4`. Значит в сегменте 34 лежит
**таблица встроенных функций**, а сегмент цели берётся из перемещений NE.

Проверка: все адреса, записанные раньше (70 → seg91:09bc, 116 → seg87:125c,
163 → seg91:06e2, 206 → seg91:0c9c, 127 → seg95:02b0, 8 → seg29:013c),
совпали с таблицей до одного. Метод прошлой работы был верный.

Отдельно сверена **таблица ширин типов** (DGROUP `0x0ca0`, 0x80 записей):
зашитая в движке совпала с настоящей **полностью, 95 из 95**.

## Разобрано и реализовано по машинному коду

* **builtin 106** (RUN87:09fe) — `offset()`: позиция подстроки с единицы, 0 при
  отсутствии; возвращает `результат − начало + 1`.
* **builtin 69** (RUN91:00b2) — вычитание чисел: `fild`/`fld` по признаку,
  затем `fsubr`; результат десятью байтами `[u16 признак][8 байт]`.
* **опкод 0x71** — семейство: `lodsw`, затем переход по таблице seg34:0x2e2e с
  индексом `(младший & 0x0f) << 1 | (младший & 0xf0)`. Младший байт задаёт
  операцию, старший — признаки. Для `0x15` (слово → десять байт) знаковый бит
  старшего байта выбирает `cdq` или обнуление `dx`, то есть 0x8315 со знаком,
  0x0315 без. Для `0x51` подобработчик отдаёт форму целиком в общий
  преобразователь seg30:0x078c, и у 0x8351 и 0x8251 его признаки совпадают.
* **builtin 116** переписан по коду (RUN87:125c): он строит значение-строку по
  указателю `приёмник + смещение`, а копирование источника делает только при
  взведённом флаге. Прежняя версия считала смещение от источника и отказывалась
  работать при нулевом флаге — а именно так книга читает заполненный буфер.
* **GetWindowsDirectory**, **getIniVar**, **fileExists** — платформенные вызовы,
  реализованные по достигнутому пути.

## Инструмент

`tools/ne16.py` — разбор 16-битного NE: дизассемблер сегмента (capstone) и
**разворачивание цепочек перемещений**, без которого цели дальних вызовов не
находятся. Плюс поиск по таблице встроенных функций.
