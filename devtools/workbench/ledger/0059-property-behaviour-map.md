# 0059 — Карта свойств по действию, раз имён нет

**Дата:** 2026-08-14
**Статус:** ✅ карта строится, ⚠️ имён по-прежнему нет
**Тип:** инструмент и разбор

Продолжение 0058. Раз имена свойств в файлах среды не находятся, соответствие
строится **по действию**: для каждого номера видно, в какую ветку разбора он
уходит и что там вызывается.

## Инструмент

`tools/propmap.py` — проходит `MTB40RUN.EXE` сегмент 66 (разбор номеров при
чтении свойства, `builtin 140`), собирает цепочки `cmp/sub ax, imm` с их
переходами и печатает для каждого номера начало ветки с разрешёнными по
перемещениям вызовами. Сейчас распознаётся 34 номера из 73 (остальные уходят
через таблицы переходов, их надо добирать отдельно).

## Что уже видно

* **`0x400f`** — мера: `MTB40UTL.5` (это `imul word [ds:2ch]`, умножение на
  масштаб единиц), затем `MTB40UTL.18` и модуль. Именно его обработчик из фона
  «Message» ставит в 12.
* **`0x4004`, `0x4022`, `0x4027`, `0x4034`** — одна общая реализация: `seg66:0x1b1a`
  разбирает их вместе и зовёт `MTB40BAS.128`, **не передавая объект** — только
  два локальных буфера. Значит это свойства среды, а не объекта.
* **`0x40db`, `0x4208`** — сразу ветка ошибки (`push 2 / push 1f55h` — код
  сообщения): свойство есть в языке, но в этой сборке не поддержано.
* **`0x4226`** уходит в `seg124`, **`0x4071`** возвращает готовую пару
  `(1, 0x400)` — то есть ссылку на корневой объект.

## Как этим пользоваться

Номер свойства из байт-кода книги — `0x4000 + индекс`. Дальше:

    tools/propmap.py

Если номера в карте нет, среда его особо не разбирает, и значение живёт в общей
базе объектов. Для таких свойств (например `0x4030`, которое читает обработчик
сообщения) движку нужны **умолчания из сериализованной книги** — это следующая
задача, и она теперь чётко отделена от разбора самих номеров.
