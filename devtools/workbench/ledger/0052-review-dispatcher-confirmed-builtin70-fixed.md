# 0052 — Проверка чужой работы: диспетчер подтверждён, builtin 70 читался наоборот

**Дата:** 2026-08-13
**Статус:** ✅ находка подтверждена, 🔴 одна семантика исправлена, ⚠️ ловушка с патчем
**Тип:** проверка и исправление

Разбор записей 0048–0051 и кода, который за ними стоит. Проверялось независимо:
своим разбором NE, своей пересборкой и своим прогоном.

## Диспетчер опкодов найден — подтверждаю

Главное из 0048 воспроизвелось полностью. В `MTB40RUN.EXE`:

* сигнатура `ac 32 e4 03 c0 8b d8 36 ff a7 88 0b`
  (`lodsb; xor ah,ah; add ax,ax; mov bx,ax; jmp ss:[bx+0x0b88]`) встречается в
  **сегменте 34 сто сорок семь раз**;
* таблица в автоматическом сегменте данных `seg127:0x0b88` — **121 запись, все
  различные, все в пределах сегмента 34**.

Случайным совпадением такое быть не может.

**Почему я не нашёл его раньше** (отменяет вывод 0026 и часть 0047):
интерпретатор — шитый код. Выборка следующего опкода не вынесена в общий цикл,
а **вклеена в конец каждого обработчика**, и переход при этом **ближний**.
Поиск косвенных *дальних* вызовов не мог его найти по построению.

И ещё: невоспроизводимое срабатывание точки останова из 0046 — `eip=0x3449` —
это ровно `seg34:0x3448 + 1`, одна из двух проверенных точек выборки.
Интерпретатор был пойман ещё тогда и не опознан.

## builtin 70 прочитан наоборот — исправлено

Адрес в 0051 указан верно: по `seg91:0x09bc` действительно точка входа, ABI
`W -> W`, `retf 2`. Неверна семантика. Байты целиком:

```
83 7e 06 01   cmp word [bp+6], 1     ; CF=1 ⟺ аргумент == 0
1b c0         sbb ax, ax             ; ax = -CF
f7 d8         neg ax                 ; ax = CF
ca 02 00      retf 2
```

То есть **1 возвращается ровно при нулевом аргументе** — это логическое «не».
В движке стояло `value >= 1 ? 1 : 0`, точное дополнение. Оба значения берутся из
одного и того же вычисленного VM числа, поэтому ветвление переворачивалось
**всегда**.

Проверено прогоном: с исправлением путь меняется немедленно — барьер
`GetWindowsDirectory @0x131b1c` исчезает, вместо него `opcode 0x6c @0x130579`.
Значит вывод 0051 «нормальная ветка MCI возвращает 1, поэтому проверка
проходит» и записанный там барьер относятся к ветке, которую оригинал в этом
месте не выбирает. Запись 0051 в этой части отменяется.

Урок в копилку метода: адрес функции подтверждается легко и обманывает редко,
а вот **пара `sbb ax,ax` / `neg ax` читается наизнанку на раз** — это идиома
«получить 0/1 из флага переноса», и знак условия у неё задаётся тем, что стоит
до неё.

## Ловушка: работа не попадала в репозиторий проекта

`scummvm-src/` лежит в `.gitignore`, правки проекта хранятся в
`patches/scummvm-director.patch`. Движок toolbook закоммичен **во вложенный
git**, и из-за этого команда пересборки патча, которой пользовались раньше,

    git diff HEAD > ../patches/scummvm-director.patch

перестала его включать: закоммиченное в `diff HEAD` не попадает. Патч отставал
на весь день работы — около 3800 строк движка существовали в одном
неотслеживаемом каталоге.

Правильная база — коммит апстрима из `patches/scummvm-base-commit.txt`:

    git diff e453f61d > ../patches/scummvm-director.patch

Заодно: индекс `LEDGER.md` отстал на четыре записи (0048–0051). Индекс — карта
проекта, без него записи не находятся.
