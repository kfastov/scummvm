# 0048 — Формальная книга разобрана; OpenScript дошёл до первого вложенного метода

**Дата:** 2026-08-13
**Статус:** 🟡 воспроизводимый checkpoint, игра ещё не запущена до меню
**Тип:** реализация, реверс и границы достоверности

## Архитектурное ограничение

Движок не содержит сценария обхода «Башни знаний». Имена игровых страниц,
роликов и кнопок не используются для выбора переходов. Эталонная Windows 98 VM
служит только оракулом: события, переходы и мультимедиа должны выбираться
сериализованными объектами и OpenScript исходной книги.

Цель также **не состоит в реализации всех опкодов ToolBook 4**. Реализуются
операции, реально достигнутые книгой в проверяемом игровом пути. Неиспользуемый
код среды может оставаться неподдержанным или безопасным no-op. Но операция,
которая меняет стек, состояние либо ветвление достигнутого обработчика, не
подменяется no-op без машинного доказательства.

## Формальная объектная модель

Жадные поиски по соседству заменены ссылками из heap:

* 261 строгий heap-сегмент: 52 Background и 209 Page;
* 209/209 Page ссылаются на Background через root `+0x4b/+0x4d`;
* 5670 typed objects, их parent handles, service child lists и порядок
  back-to-front разрешаются внутри владельца;
* видимость берётся из `flags+0x23 bit0` и наследуется от Group;
* 2393/2393 Picture имеют валидную ссылку `+0x55` на DIB;
* Field text читается по цепочке descriptor -> text block;
* формальная таблица порядка содержит все 209 Page и задаёт начальную страницу.

Потоки картинок теперь покрывают обычные chunk streams, 64-КБ huge spans,
несжатые `compSize=0` spans и смешанные local/tail layouts. На полном корпусе
формальный locator валидировал 170 tails / 1322 Picture; 28 tails используют
huge span, 24 — несжатые spans. Отдельные smoke-проверки подтвердили Main,
Tower и страницу истории `s0_1`, при этом код не выбирает их по имени.

## Скрипты и привязка владельца

Разобран directory `0x0225` с записями `{eventSelector, recordOffset}`. Внешняя
таблица ScriptObject найдена структурно и единственна: 192 объекта, 1622
обработчика. Для root `+0x2e` и object `+0x0f` действует одно правило:

1. строгий local directory выигрывает;
2. иначе ненулевое поле кодирует `ScriptObject.id + 1`.

Все ненулевые привязки корпуса разрешаются. Начальная Page таким образом
получает shared ScriptObject id 463, а её настоящий `firstIdle` начинает
исполняться. Это не переход, прописанный в C++.

## OpenScript VM: достигнутый путь

Интерпретатор учитывает фактическую ширину W/D/extended значений и реализует
только машинно подтверждённые операции достигнутого обработчика. Среди них:

* локальные значения, константы, ветвления, cleanup и coercion;
* системные/builtin вызовы, использованные начальным `firstIdle`;
* globals, concat, equality/not-contains, AnsiUpper;
* `linkDLL`: пять бинарных каталогов native definitions найдены строгим
  validator без ложных совпадений и зарегистрированы по сериализованным именам;
* `op6d` читает формальный selector+identifier и сначала разрешает метод в
  контексте, затем зарегистрированную native definition;
* `op73` оставлен value-owned no-op только после доказательства, что это
  `VALUECOPY` in-place без изменения ширины стека.

Фактическая достигнутая граница: `firstIdle` ScriptObject 463 вызывает свой
метод selector `0x6224` `getWinPointer` (код книги `0x1316cf`). Метод выделяет
128 байт через объявленные книгой `GlobalAlloc`/`GlobalLock`. Нужен общий
вложенный вызов handler с implicit context/аргументами и возвращаемым D; сейчас
движок честно останавливает этот handler.

## Native definitions и шрифт

Каталог `linkDLL` — не строковый токен. Его entry содержит name offsets,
ordinal, thunk offset и длины thunk/signature. Строгая проверка на всём файле
находит ровно пять каталогов: GDI, USER, KERNEL, TB40WIN и TB40DOS.

Первый реально вызванный extension — `displayFonts`. Оригинал возвращает строки
`face,size,...\r\n`. Книга сама проверяет наличие `CBook # 2`; если его нет,
она строит путь `workPath + cbook2.fon` и вызывает `AddFontResource`.
`CBOOK2.FON` формально содержит шесть размеров лица `CBook # 2` (8, 10, 12,
14, 18, 24). Поэтому установка шрифта будет реализована общим разбором
FONTDIR/FONT, а не специальной веткой по имени этой игры.

## Известные ограничения checkpoint

* implicit CDB slots ещё не представлены полноценно; slot 0 — runtime context
  field `+0x16`, а не Page owner. Текущий stub превращает `workPath` в `"0"`,
  что видно в диагностических module keys и должно быть исправлено до проверки
  файловых операций;
* `op6d` ещё не исполняет вложенный OpenScript handler и не поддерживает общий
  native marshaller;
* multimedia/MCI, timers, save/load и основной gameplay пока не достигнуты;
* Viewer origin — runtime state, не выводится из малого Background canvas;
* до эталонного меню и первого игрового экрана ScummVM пока не дошёл.
