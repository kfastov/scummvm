# 0037 — Объектная модель из кучи: обводы вместо прямоугольников

**Дата:** 2026-08-13
**Статус:** ✅
**Тип:** формат и реализация

Проход по куче (0031) довёл до настоящего разбора объектов. Объект лежит
**тремя блоками подряд**:

    [свойства, тип 0x10/0x08/0x15]   рамка и число вершин
    [имя, тип 0]                     `[u32 самоссылка][имя\0]`
    [обвод либо DIB, тип 0]          список вершин или картинка

**Проверка на кнопке `tower` карты башни.** В блоке свойств рамка
`(750,645)-(1335,1635)` в единицах 1/1440 дюйма, то есть `(50,43)-(89,109)` в
точках, и поле «число вершин» = 13. В следующем блоке ровно 13 пар координат,
все кратны 15: `(60,104) (50,73) (51,58) (56,49) (63,62) (72,43) (83,68)
(85,80) (89,85) (88,96) (84,99) (82,106) (71,109)`. Совпало и число, и рамка —
это обвод башни на карте.

То есть кнопки в игре — **многоугольники**, а не прямоугольники: класс
`IrregularPolygon` из таблицы классов. Прежняя эвристика (0028) давала только
описанный прямоугольник, и соседние кнопки на карте перекрывались.

## Что в движке

`scanObjects` переписан: вместо поиска «четырёх u16, кратных 15» по всей книге
идёт обход цепочки блоков. Вход в цепочку — блок с DIB, у которого известна
длина, отсюда база сегмента. Найдено **1218 объектов** с проверенными рамками;
у многоугольных заполнен обвод.

* попадание мышью считается по обводу (луч вправо, чётность пересечений), рамка
  служит грубой отсечкой;
* клавиша `o` рисует обводы, а не рамки.

На карте башни это видно глазом: белые обводы ложатся на домики, лодку,
дракона и вулкан.

**Осознанное ограничение:** объекты, лежащие в сегменте до первой картинки, не
находятся — вход в цепочку только через блок DIB. Их можно будет добрать, если
найдётся способ определить начало сегмента.
