# 0017 — Баг движка: «@» в пути фильма считался корнем игры

**Дата:** 2026-08-12
**Статус:** ✅ исправлено
**Тип:** ошибка ScummVM (кандидат в апстрим)

**Симптом, три штуки сразу:** из локации не работала кнопка «в город» (движок
падал на `Archive::openFile(): Error opening file Turm/main.DIR`), не звучала ни
одна озвучка (`Failed to open xf003`, `xf027`, `stadt`), и `the pathName`
внутри локации был `C:\Turm\` вместо `C:\Datas\Turm\`.

**Причина одна.** Игра переходит в локацию так: `go movie "@:Markt:Markt"`. В
Director `@` — это папка **текущего фильма**; фильмы лежат в `Datas\`, значит
путь означает `Datas\Markt\Markt`. ScummVM считал `@` корнем игры
(`rectifyRelativePath`: «relative to the top level»), да ещё и объявлял такой
путь абсолютным (`isAbsolutePath`), поэтому поиск шёл мимо текущей папки и
находил фильм по имени во всём дереве — с ответом `Markt/Markt.DIR`, без папки.

Дальше расходится всё: окно берёт из этого пути свою текущую папку (`Markt\`),
игра строит от неё пути к звукам (`suchpfad` добавляет `<путь>Sounds\x\` и путь
на уровень выше) — оба не существуют; а `go(1, "main")` из локации ищет
`main.DIR` относительно несуществующей папки.

**Правка:** `@` — относительный маркер, а не абсолютный путь.
`isAbsolutePath` больше не считает его абсолютным, `isPathWithRelativeMarkers`
теперь его признаёт, а `rectifyRelativePath` разбирает его относительно
текущей папки, а не очищая базу.

Заодно в `findPath` поиск по `the searchPath` игры переставлен **перед**
запасным поиском по всему дереву: запасной ищет по имени и отвечает именем без
папки, пряча настоящее место файла.

**Проверено положительным признаком:** после правки `the pathName` в локации —
`C:\Datas\TURM\`, в логе прогона **ноль** сообщений `Failed to open`, обход всех
семи локаций проходит с возвратом в город.
