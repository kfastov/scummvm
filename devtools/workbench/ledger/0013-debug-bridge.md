# 0013 — Отладочный мост в движке и инструменты поверх него

**Дата:** 2026-08-12
**Статус:** ✅
**Тип:** инструмент

Диагностика по логам упёрлась в свой потолок: прогон растил гигабайтные файлы,
нужный момент в них приходилось ловить заранее заданными флагами, а спросить
живой движок было нечем.

**Мост** (`engines/director/debug-bridge.{h,cpp}`, ключ `debugbridge_port`):
движок слушает localhost, принимает команду в строке, отвечает строкой JSON.
Обслуживается из `pollEvent`, то есть отвечает и когда игра стоит в `go the frame`.

Свои команды: `state`, `sprites [all]`, `hit X Y`, `behaviors CH` (поведения,
экземпляры, спан спрайта и **сырые блоки деталей из файла**), `castinfo`,
`shot ПУТЬ`, `event CH ИМЯ`, `click/down/up/move/key`.

Всё прочее уходит в штатную консоль ScummVM — для этого в `gui/debugger.cpp`
добавлен перехват вывода (`runCapturedCommand`). Так стали доступны `channels`,
`cast`, `var`, `funcs`, `bt`, `disasm`, точки останова — без открытия консоли,
которую в безоконном прогоне показать негде.

**Клиенты:** `tools/svmdbg` (командная строка) и `tools/svmbridge/mcp_server.py`
(MCP-сервер) поверх общего `tools/svmbridge/core.py`. Запуск прогона ждёт ответа
моста и, не дождавшись, поднимает ошибку с хвостом лога — «вроде запустилось»
не возвращается никогда.

**Чем сразу окупился:** снимок экрана по требованию вместо перебора кадров, и
разбор канала с сырыми байтами файла рядом — именно он вскрыл 0014.
