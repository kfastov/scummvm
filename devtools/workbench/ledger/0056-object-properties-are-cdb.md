# 0056 — Свойства объектов: это база CDB, а не поля записи

**Дата:** 2026-08-13
**Статус:** ✅ механизм найден, ⚠️ умолчания свойств не читаются
**Тип:** разбор чужого кода и реализация

Барьер из 0055 — `builtin 139` — разобран до конца, и заодно стало понятно
устройство свойств целиком.

## Цепочка

`builtin 139` (RUN81:0x021c) ветвится по **классу объекта**:
`байт[bp+0dh] and 0FCh`. Класс `0x40` означает неразрешённую ссылку: тогда
вызывается `seg81:0x1386`, который через `MTB40BAS.131/132` превращает ссылку в
конкретный объект и **заново входит в 0x021c** (таблица операций
`seg81:0x13f2`, 14 входов; наш случай — вход 1).

У конкретного объекта (классы `0x50/0x54/0x58`, `0x64`) сначала идёт разбор
нескольких **системных** свойств по номерам — `0x4226`, `0x40e2`, `0x401f`,
`0x4059`, `0x40de`, `0x41f2`, `0x41ff`, `0x4208`, `0x4285`, — а всё остальное
уходит общим путём в `seg8:0x04ea`, и тот зовёт

    MTB40BAS.CDBSetValueEx

То есть **свойства объектов хранятся в базе объектов CDB**, а не разложены по
полям записи. Чтение — `builtin 140` (RUN66:0x0726, `retf 6`, внутри
`MTB40BAS.37`).

Найденные варианты:

| builtin | что делает | аргументы |
|---|---|---|
| 139 | запись свойства словом | объект, значение (W), номер |
| 143 | запись свойства значением D | объект, значение (D), номер |
| 140 | чтение свойства | объект, номер |

Соответствие «номер → имя» пока **не установлено**. Проверенная гипотеза
«номер = индекс в таблице имён компилятора со сдвигом 0x4000» отклонена:
системные номера ложатся на правдоподобные имена (`syslinestyle`, `keycancel`,
`keyback`, `showhotwords`, `spectrumpalette`, `startupunits`), но номера,
которыми пользуется книга, дают бессмыслицу (`abouttoolbook`, `checkbox`,
`back`, `an`). Таблица имён в `MTB40CMP.DLL` разобрана до конца (975 имён,
массив смещений по 0x4be5e, строки с 0x4c5fc, порядок совпадает), так что дело
не в разборе — номера просто из другого пространства.

## Реализовано

В движке заведено хранилище свойств по паре «имя объекта, номер» — ровно то
наблюдаемое поведение, что даёт CDB: что записали, то и читается. Плюс два
опкода, разобранных по коду:

* **0x48** (RUN34:0x179e) — прибавление единицы к четырёхбайтовому значению:
  `inc` младшего слова, при переносе `inc` старшего;
* **0x49** (RUN34:0x1883) — сравнение двух четырёхбайтовых значений: старшие
  слова со знаком, при равенстве младшие без знака; кладётся слово 1, если
  верхнее не меньше следующего.

После этого стартовый скрипт дошёл до самого показа сообщения: обработчик из
фона «Message» ставит свойства `0x400f := 12` и `0x402e := ""`, читает `0x4030`
и собирает текст.

## Чего не хватает

**Умолчаний.** Наше хранилище пустое, пока книга сама что-то не запишет, а у
оригинала CDB отдаёт значение из сериализованной записи объекта. Первое же
чтение (`0x4030` у «Message») это показало: свойство не ставилось, движок вернул
пустую строку. Дальше книга собирает сообщение, в котором есть строка
«Не найден файл», — и это ровно тот случай, о котором предупреждает метод:
выдуманное значение может увести в чужую ветку.

Следующий шаг — не подбирать умолчания, а прочитать, откуда их берёт
`MTB40BAS.37` (CDBGetValue): по какому полю записи объекта он ищет номер
свойства. Тогда движок сможет отдавать настоящие значения книги, а не пустоту.
