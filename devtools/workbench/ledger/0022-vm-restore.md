# 0021 — Виртуалка: восстановление стенда и почему падал рантайм

**Дата:** 2026-08-12
**Статус:** ✅
**Тип:** стенд

Стенд понадобился как источник эталона для 0020 и оказался сломан. Что
выяснилось — чтобы не терять на этом время второй раз.

**Рантайм ToolBook падал на пустом месте.** `MTB40RUN.EXE` выдавал
«general protection fault in module MMSYSTEM.DLL» **даже запущенный без книги**.
То есть дело было не в игре. Причина — грязное состояние гостя: QEMU дважды
снимался `kill -9` при работающей Windows. После отката на снимок
`clean-desktop` тот же рантайм с того же CD поднимается и рисует заставку.

**Снимок не поднимался из-за версии QEMU.** `-loadvm` ругался: «Machine type
received is 'pc-i440fx-10.1' and local is 'pc-i440fx-11.0'». Снимок можно
поднять только на том типе машины, на котором он снят, поэтому в `3-vm.sh`
добавлена переменная `MACHINE`:

    MACHINE=pc-i440fx-10.1 LOADVM=clean-desktop ./3-vm.sh run bashnya

**Игра ставится не туда, куда помнилось.** На диске гостя лежит только книга
`C:\NMG\KNTOWER\KNTOWER.TBC` (1,26 МБ) — сам рантайм и полная книга остаются на
компакт-диске (`D:\KNTOWER.EXE`, 38 МБ). Ярлыка в меню «Пуск» нет: группа
«New Media Generation» пустая.

**Игра поставлена и снята снимком.** `D:\SETUP.EXE` проходит по клавише Enter
(кнопки книги ToolBook отзываются на неё как на «продолжить»); в конце он просит
перезагрузку — окно закрывается по `alt-f4`, после чего игра запускается из меню
«Пуск». Состояние сохранено как снимок **`bashnya-installed`**:

    MACHINE=pc-i440fx-10.1 LOADVM=bashnya-installed ./3-vm.sh run bashnya

**Мышь: гость удваивает сдвиги.** Курсора в `screendump` не видно, пока его не
нарисует сама программа, поэтому промахи выглядели как «мышь не работает».
На кадре игры курсор оказался виден: запрос (300,197) увёл его в (610,400) —
ровно вдвое. В `tools/qmon.py` добавлен коэффициент `MOUSE_SCALE` (по умолчанию
2, переопределяется через `QMON_MOUSE_SCALE`). После этого клик по пункту меню
попадает с первого раза.

**Чем полезен монитор QEMU.** `pmemsave 0 0x10000000 файл` снимает физическую
память гостя целиком; в ней находятся распакованные картинки (искать по
образцу из своей распаковки). Важная оговорка: память **физическая**, поэтому
виртуально непрерывный буфер разложен по страницам в 4 КБ и подряд читается
только внутри страницы.

**Установленная книга достаётся из образа диска.** В `vm/win98.qcow2` сигнатура
`\x03JBO` встречается ровно один раз (0x19e79b31) — оттуда вынимается
`KNTOWER.TBC`, 1 263 919 байт. Ожидание не оправдалось: в ней всего 3 страницы
и 7 картинок, ни одной полноэкранной. Значит меню и вступление игра берёт с
компакт-диска, а установленная книга — только запускатель.
