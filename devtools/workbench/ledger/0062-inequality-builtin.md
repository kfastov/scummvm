# 0062 — Ветка ошибки была из-за перепутанных равенства и неравенства

**Дата:** 2026-08-14
**Статус:** ✅ стартовая проверка проходит
**Тип:** отладка и исправление

Расхождение из 0061 (эталон доходит до ввода имени, движок уходит в сообщение
«Не найден файл») найдено полностью.

## Как искалось

В движок добавлены две трассировки, обе универсальные:

* `-d 5` — каждое условное ветвление: адрес, значение условия, взят ли переход;
* `-d 3` — вызов вложенного обработчика книги и **его возвращаемое значение**.

Этого хватило за один прогон:

```
ToolBook: вызов обработчика myFileAttributes @0x13213b
ToolBook: myFileAttributes вернул «false» (число 0)
ToolBook: ветвление 14 @0x132147 условие=1 переход=0
```

То есть книга спрашивает `myFileAttributes`, получает «false», и `not` от него
уводит в сообщение об ошибке.

## Что оказалось не так

`myFileAttributes` устроен просто: зовёт `SetFileAttributes(файл, "A")`,
сравнивает результат с 1 и возвращает `"true"`/`"false"`.

Проверено по коду расширения: `TB40DOS.SETFILEATTRIBUTES` (ordinal 12,
seg3:0x1198) возвращает **1 при успехе**, `0xFFFE` при пустом имени и
отрицательное значение при ошибке DOS. Наш движок возвращает 1 — верно.

Значит ошибка в сравнении. И она нашлась: **builtin 194 и 198 идут в один и тот
же помощник `RUN91:0x1da2`, различаясь единственным аргументом** — 194 кладёт
`1`, 198 кладёт `0`. Помощник считает равенство и в конце делает

```
cmp  ax, [bp+0ch]     ; сравнить «равны ли» с этим флагом
je   вернуть 1
jmp  вернуть 0
```

То есть возвращает 1, когда результат сравнения **совпал с флагом**. Отсюда:
**194 — равенство, 198 — неравенство**. В движке оба считались равенством.

С исправлением: `setFileAttributes` вернул 1, `1 <> 1` = ложь, переход по
`0x14` берётся, обработчик возвращает `"true"`, и книга спокойно идёт дальше —
ровно как на эталоне.

Это третий случай той же породы, что builtin 70 (0052): условие, перевёрнутое
на один шаг. Проверять сравнения по коду теперь правило, а не пожелание.

## Попутно подтверждено машинным кодом

* `0x13` — переход, если условие истинно; `0x14` — если ложно (`or cx,cx` и
  `jne`/`je` в RUN34:0x119f и 0x11ec). Наша трактовка верна.
* `0x2f`, `0x30`, `0x31`, `0x77` начинаются с `mov bx,sp` — **операндов нет**;
  `0x33` начинается с `lodsb` — байт операнда есть. Разбор длин верен.

## Новый барьер

    ToolBook: builtin 212 @0x1303a7 пока не реализован
      операнд [-0]: «\»

`builtin 212` (RUN86:0x00ea) берёт длину строки через `KERNEL.90`, зовёт
`MTB40BAS.69` (поиск подстроки) и собирает результат через `MTB40BAS.109`.
Похоже на поиск разделителя пути — следующая задача.
