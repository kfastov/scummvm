# 0040 — О методе: где искать ответ, а где его нет

**Дата:** 2026-08-13
**Статус:** ✅ правило записано в `CLAUDE.md`
**Тип:** о методе (продолжение 0012)

Замечание по ходу работы, которое стоило нескольких часов и потому записано
отдельно.

## Что даёт результат

**Отладка живого оригинала.** Эталон в QEMU полезен не только для сверки
кадров:

* трассировка блочного слоя (`-trace blk_co_preadv`) за минуту показала, что
  игра читает книгу сплошными кусками по ~60 КБ (0038);
* `pmemsave` дал эталонные байты и свёл подозрения к двум записям из
  38 621 (0035);
* заглушка GDB (`-s`) даёт точки останова и кадр стека.

**Чтение машинного кода среды.** Вся среда ToolBook лежит на том же диске.
Поиск характерной константы — `cmp al, 0xf5`, то есть байты `3c f5` — вывел
прямо на распаковщик картинок **за один запрос**, и алгоритм прочитан целиком
(0039).

**Свой инструмент под задачу.** Перебор не влезал в Python — появились
маленькие программы на C (`tools/rle/`). Нужен воспроизводимый обход —
сценарий ввода в движке. Нужно спросить живой движок — отладочный мост (0013).

**Проверка глазами.** Числовые меры обманывали трижды: `c+3` против `c+4`
(0025, 0027), куски по 2048 (0034). Картинка каждый раз решала спор за один
взгляд.

## Что результата не даёт

**Перебор гипотез по одному файлу данных.** Полосы в картинках: четыре версии
подряд, все проверены и отпали (0034) — часы работы. Ответ пришёл из машинного
кода за один запрос.

**Вывод формата «по согласованности».** Длины операндов OpenScript через
распространение ограничений не сузились вовсе (0023).

**Доверие числовому совпадению без картинки.** Критерий «выход ровно `rawSize`
и вход ровно `compSize`» в окне 8 КБ даёт 907 ложных совпадений (0029).

## Правило

Если вопрос про **поведение** программы — идти в отладчик или в её код. Файл с
данными отвечает только на вопрос «что лежит», и то не всегда.

Правило и список ловушек стенда вынесены в `CLAUDE.md`, чтобы попадать в
контекст каждой сессии, а не всплывать по памяти.
