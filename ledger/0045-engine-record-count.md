# 0045 — Движок распаковывает как оригинал: по числу записей

**Дата:** 2026-08-13
**Статус:** ⚠️ внедрено, покрытие пока частичное
**Тип:** реализация

В движок перенесено то, что прочитано в коде среды (0039, 0042) и подтверждено
отладчиком (0044):

* `unpackChunks` повторяет `MTB40BAS.DLL` буквально: поток — куски вида
  `[u16 число записей][записи…]`, цикл идёт **заданное число раз**, а не «пока
  не заполнится приёмник»;
* поиск начала потока: сперва проверяются ближайшие положения сразу за блоком
  DIB (шаги 4…64 байта) — по замеру у 11 картинок из 12 найденных поток стоит
  ровно через **4 байта** после палитры, то есть это следующий блок кучи;
  у случая, пойманного отладчиком, — через 26 (между ними мелкий блок);
* прежний жадный поиск по сегменту оставлен запасным путём.

**Покрытие.** На выборке из 40 картинок правило находит поток у 12. Крупные
фоны 640×480 по-прежнему не находятся: их поток разбит на куски по 65536 и
лежит в других сегментах. Регрессии нет — заставка «БАШНЯ ЗНАНИЙ» рисуется, как
и раньше, через запасной путь.

Дальше по картинкам: поймать отладчиком загрузку страницы с фоном 640×480 и
увидеть, откуда берутся куски 2..N.
