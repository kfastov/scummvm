# 0030 — Серия не обрывается на конце строки: правило из 0021 было неверным

**Дата:** 2026-08-13
**Статус:** ✅ проверено картинкой
**Тип:** формат, отмена прежнего решения

В 0021 записано: «серия обрывается на конце строки картинки; без этого правила
распаковка давала на 180–212 байт больше нужного». Правило принято потому, что
с ним **сходился размер**. Картинку при этом никто не смотрел целиком.

**Смотрю целиком.** Заставка `424×373`, данные сразу за палитрой:

* с обрезкой — изображение «съезжает»: каждая строка сдвинута относительно
  предыдущей, весь кадр идёт наискось, текст читается только по кусочкам;
* без обрезки — замок, небо и надпись «Подождите немного / Программа проверяет
  настройки компьютера…» на своих местах. Остаются два горизонтальных разрыва,
  где картинка скачком сдвигается вбок.

То есть **серии переходят на следующую строку**, как в обычном RLE, а прежние
«180–212 лишних байт» — это не повод обрезать, а признак тех самых разрывов.

Правило теперь: `c <= 0xf5` — серия длиной `c + 3`; `c > 0xf5` — `c − 0xf5`
литеральных байт; строк поток не знает вовсе. Движок и `tools/tbk.py`
исправлены.

## Что это ломает в прежних выводах

Записи 0025 и 0027 сравнивали варианты по совпадению размеров при **неверном**
правиле, поэтому их числа смысла не имеют. Заодно подтверждается 0029: критерий
«размеры сошлись» ненадёжен сам по себе — единственная настоящая проверка это
глаз.

## Что открыто

**Полноэкранные фоны так и не находятся.** Проверены все 57 заголовков
`640×480×8`: при верном правиле **ни у одного** данные не лежат сразу за
палитрой (прежние «три годных» были случайностью обрезки). Поиск по окну ±2 МБ
с двухступенчатым фильтром даёт 14 кандидатов, и все при распаковке дают шум —
значит данные полноэкранных фонов адресуются иначе, а не лежат рядом.

Зацепка прежняя (0029): сразу за палитрой у них начинается запись со ссылкой
`14 00 <u16>`. Следующий шаг — разобрать эту ссылку.

Инструменты для опытов сложены в `tools/rle/`: `find2.c` (поиск начала данных с
дешёвым фильтром по соотношению вход/выход) и `dump.c` (распаковка в BMP, чтобы
смотреть глазами, а не на числа).
