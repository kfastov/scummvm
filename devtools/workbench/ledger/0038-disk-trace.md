# 0038 — Трассировка чтений: игра читает книгу цельными кусками по ~60 КБ

**Дата:** 2026-08-13
**Статус:** ✅ приём работает, первый результат получен
**Тип:** метод

Перебор эвристик по картинкам себя исчерпал (0034, 0036). Правильный вопрос —
не «где лежат пиксели», а **что и откуда читает сама программа**. На это прямо
отвечает трассировка блочного слоя QEMU.

## Как

    printf 'blk_co_preadv\n' > /tmp/trace-events.txt
    qemu-system-i386 … -trace events=/tmp/trace-events.txt,file=/tmp/qemu-trace.bin

Файл трассировки — обычный текст, строка на чтение:

    blk_co_preadv blk 0x7a8df0400 bs 0x7a9052c00 offset 39641088 bytes 2048

Смещения — в файле образа. Книга внутри образа: `KNTOWER.EXE` начинается с
`0xa800`, книга внутри него с `0x29e0`, значит смещение в книге равно
`offset − 0xd1e0`.

**Важно:** запускать надо с тем же набором устройств, что в снимке, иначе
`-loadvm` ругается «Unknown section or instance 'sb16'».

## Что увидели

Экран «введи своё имя», нажатие «да»:

* до нажатия — 23 чтения по смещениям около 39,6 МБ, **за пределами**
  `KNTOWER.EXE`: это звук с диска (`WAV/…`), игра его стримит;
* после нажатия — **30 чтений подряд по 2048 байт**, все внутри книги, сплошным
  диапазоном `0x89de20 … 0x8ac620`, то есть ровно `0xF000` ≈ 60 КБ.

В этот же диапазон попадают и заголовок картинки `@0x8a484f` (640×480), и её
пиксельный поток `@0x8a6caf`, найденный раньше жадным сопоставлением.

## Вывод

**Игра подгружает книгу целыми сегментами примерно по 60 КБ**, а не отдельными
картинками. Это подтверждает сегментную модель из 0031: страница со всеми
объектами, заголовками картинок и пиксельными потоками лежит в одном сегменте и
читается как единое целое. Заодно это даёт способ определять границы сегментов
**наблюдением**, а не подбором: одна страница — один сплошной прогон чтений.

Следующий шаг подсказан там же: у QEMU есть заглушка GDB (`-s`), то есть можно
поставить точку останова на распаковщик и посмотреть параметры вызова —
откуда он берёт начало потока и что делает с двумя «фантомными» записями
(0035).
